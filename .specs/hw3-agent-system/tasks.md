# ДЗ3 · Agent System — план реалізації

Послідовність відповідає розділам design.md. Сценарії фіксуються до фінального прогону, результати додаються за фактом.

- [ ] **T01. Узгодити межі реалізації.** Погодити окремий пакет, MCP SDK і SQLite. Вибрати модель із tool calling та профіль лімітів. Для платного профілю окремо узгодити тариф, оцінку й бюджет перед викликами. Зафіксувати початковий зріз корпусу ДЗ2. → Організація коду, перевірка та ризики · R01, R02, R05, R07, R11, R12.
- [ ] **T02. Описати інструменти й додати retrieval-адаптер.** Створити versioned system prompt, описи, схеми аргументів і результатів та changelog у `prompts/hw3/`. Під’єднати `Retriever.search` із підмножиною доступу, зберегти ID і походження доказів, перевірити типи й межі. → Інструменти й доступ · R01, R03, R06, R07.
- [ ] **T03. Реалізувати обмежений цикл.** Додати адаптер tool calling, валідацію цитат, облік кроків/бюджету/дедлайнів, завершення воркера, частковий результат і trace. Додати fault-обгортку та обмежені повтори read-only викликів. → Цикл, стан і збої · R01–R03, R07, R11.
- [ ] **T04. Під’єднати MCP через stdio.** Реалізувати читання картки джерела, серверну перевірку доступу й інтеграційний тест виклику агентом. Перевірити відмову, відсутність доступу через retrieval і валідацію відповіді клієнтом. → Інструменти й доступ · R03, R05, R06.
- [ ] **T05. Реалізувати пам’ять, feedback і підкоманду.** Додати обмежену історію сесії, валідацію відгуку, явне підтвердження, ізоляцію та ідемпотентний запис. Під’єднати CLI, перевірити повтор після розриву і вплив відгуку на наступну відповідь. Перевірити старі точки запуску. → Організація коду, пам’ять, підтвердження і дані · R04, R08, R09, R12.
- [ ] **T06. Зібрати й перевірити eval-набір.** Додати контрольні документи в окремий профіль, реалізувати перевірки з матриці нижче та офлайн-запуск зі сценарною моделлю. Відділити тестові еталони від вхідних даних агента. → Перевірка та ризики · R02–R10.
- [ ] **T07. Виконати фінальне оцінювання.** Запустити набір із реальною моделлю в погодженому профілі, зберегти артефакти першого та фінального прогонів, повторити нестабільні сценарії. У `evals/hw3/REPORT.md` звести метрики, документи/trace для трьох фактичних провалів і таблицю збоїв. → Перевірка та ризики · R10, R11.
- [ ] **T08. Підготувати здачу.** Перевірити відтворення за README, задокументувати межі доступу MCP, обслуговування пам’яті й feedback та додати `REFLECTION.md` із фактичними епізодами. Після завершення реалізації зафіксувати результат у журналі змін і перевірити вимоги до GitHub-доступу. → Організація коду, перевірка та ризики · R05, R08, R09, R11–R13.
