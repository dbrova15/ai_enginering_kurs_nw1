# Контракти Schema v2 та повторний експеримент

## Технічний стан 26.10.2026

Завершено етап A (офлайн), окремо дозволений [етап B](../results/probes/schema-v2-enums-1/20261026T172803893529Z/PROBE.md) і після нового погодження [етап C: 240 генерацій](../results/schema-v2-enums-1/EXPERIMENT_20261026T173328975361Z.md). У C фінально валідні 220/240, OpenAI API-вартість $0.044028 із дозволених $0.25. [Новий REPORT](../REPORT.md) має статус чернетки до авторського рішення. Старі вимірювання відокремлені й не замінені.

## Межа сумісності

| Контракт | Призначення | Списки | Генерація |
| --- | --- | --- | --- |
| `schema-v2-strings-1` | 240 історичних відповідей, старі метрики й REPORT | довільні `str`, повтори допускалися | відключена |
| `schema-v2-enums-1` | нові результати | канонічні enum, без повторів | єдиний чинний контракт |

Вісім полів і їхня предметна семантика не змінені. Посилення допустимих значень є зміною контракту, навіть за однакового `schema_version: v2`. Моделі визначені в `schema_contracts.py`; `main.DevicePosting` залишився доступним через імпорт. Legacy-модель відтворює попередню JSON Schema та використовується лише для читання історії.

Нові платформи: `arduino`, `esp32`, `esp8266`, `stm32`, `raspberry_pi`, `orange_pi`.

Нові інтерфейси: `wifi`, `bluetooth`, `lora`, `i2c`, `spi`, `uart`, `usb`.

Усі поля обов'язкові; `null`, зайві поля, неканонічні значення та неправильні типи заборонені. Порожні списки дозволені. Регістр, aliases, пробіли й дублікати не виправляються. Унікальність перевіряє локальний Pydantic-валідатор; `uniqueItems` у wire-схему не додається. Після невалідної відповіді зберігаються її текст і помилка, дозволений один repair; повторна помилка дає `failed`.

`contract_sha256` — SHA-256 UTF-8 JSON із `sort_keys=True`, `separators=(",", ":")`, `ensure_ascii=False` для `contract_descriptor(version)`: version, JSON Schema, strict_validation та unique_list_fields. Це відбиток і wire-схеми, і локальних правил, а не лише JSON Schema.

Поточний SHA-256 нового контракту: `716c3e2eb27595c31177e4a6ea391c370a1e0bd8816940fc98e40ef47284a35f`.

Тільки старі записи Schema v2 без **обох** contract-полів трактуються як legacy. Частково задані поля, невідомий ID, неправильний хеш та змішані контракти відхиляються. Старі звіти `schema-v2-exact-set-v1` / `run-metrics-v1` читаються як legacy; нові звіти v2 мають явні contract version/hash. Старі JSONL і звіти не конвертуються й не перезаписуються.

## Провайдер і журнали

`LLM_PROVIDER` читається з оточення або `.env`, типово `openrouter`. Допустимі `openai`, `openrouter`, `ollama`; невідоме значення відхиляється до мережі. OpenAI/OpenRouter використовують власні ключі; Ollama не потребує зовнішнього ключа. Змінні процесу мають пріоритет над `.env`.

Нові JSONL зберігають provider, requested_model та сумісний alias model, actual_model (або null), contract version/hash, prompt version/hash, sampling, source/input hashes та preparation version. `result.first_attempt_status` відрізняє valid/invalid/refused/incomplete/empty/api_error; фінальний `result.status`, repair_attempted, відповіді спроб, latency й usage залишаються окремими. Фактична модель також зберігається для кожної відповіді. Текст мережевої помилки не журналюється, щоб не переносити ключі чи приватну конфігурацію в результати; зберігаються тип і HTTP-статус.

Типова нова папка: `results/schema-v2-enums-1/`. Старі CLI-аргументи `v1|v2`, `--limit`, `--output` збережені. `--output` дозволяє власну папку; контракт визначається за вмістом, а не назвою файлу. Ключі не записуються.

## Офлайнове оцінювання

```powershell
# Після появи нових результатів:
python evaluator.py --contract schema-v2-enums-1
python aggregate_runs.py --contract schema-v2-enums-1
# Відтворення історії окремо:
python evaluator.py --contract schema-v2-strings-1
python aggregate_runs.py --contract schema-v2-strings-1
```

Без явних файлів пошук охоплює старий корінь results і нову папку. Аргумент contract вибирає один відомий контракт; без аргументу змішаний набір відхиляється. Явно задані файли іншого контракту — помилка. Невідомий контракт ніколи не пропускається мовчки.

Одиничні поля порівнюються точно, списки — exact-set; micro precision/recall/F1 звітуються окремо. Немає fuzzy/semantic matching, нормалізації aliases чи видалення дублікатів. Нові enum і unique перевіряються до порівняння; legacy зберігає старі правила, включно з допустимими дублікатами. Використовується фінальний результат після repair. Missing/failed/invalid отримують нуль за всі поля й залишаються у знаменниках; їхнє спискове передбачення для P/R/F1 вважається порожнім.

`field_accuracy` показує всі вісім полів. `aggregate_accuracy` — середнє восьми accuracy; `content_accuracy` — середнє семи без language, також є content_field_accuracy. Якщо правильна лише мова, aggregate=1/8, content=0. Якщо неправильна лише мова — aggregate=7/8, content=1.

ID та source/input hashes звіряються між прогонами. Для нового контракту evaluator також перевіряє відповідність ID імені TXT, фактичні байти джерела й детерміновано підготовлений input. При перенесенні репозиторію відсутній старий source_path відновлюється лише через єдиний TXT з тим самим ID у чинній папці текстів. Конфлікт чи недоступне джерело — помилка.

Нові звіти зберігаються в `results/evaluation/<contract>/` і `results/metrics/<contract>/`. Генератор зіставляє лише звіти одного контракту, повторно перевіряє їх за первинними JSONL; типовий вихід `REPORT.<contract>.draft.md`. Історичний REPORT не замінюється. Нові чернетки містять обидві aggregate-метрики. Production-рішення, причини помилок та остаточний звіт залишаються за автором.

## План наступних етапів

Наведені нижче етапи B/C вже виконані за окремими дозволами; це збережений план і кошторис, а не дозвіл на новий запуск. Фактичні результати C: 8×30 первинних генерацій, 42 repair (усі Ollama), 20 failed; 120 OpenAI HTTP-запитів, 270244 input / 5819 output tokens, $0.044028. Нові запуски потребують нового погодження. Незмінені промпти й golden підтверджені SHA-256.

Етап B потребує **окремого дозволу**, як прямо встановлено в завданні користувача. Один короткий синтетичний текст, який не належить golden, передається OpenAI `gpt-4o-mini` та Ollama `llama3.2:3b` з незміненим v1, temperature=0, top_p=1. Перевіряються прийняття wire-схеми, канонічні enum, локальна валідація та метадані; repair перевіряється, якщо реальна відповідь його потребуватиме. Штучні помилки repair уже покриті офлайн-тестами. Перед пробами перевіряються активна конфігурація й наявність локальної моделі без її завантаження. Непідтримуваний endpoint не є приводом послабити локальний контракт. Запити probes зберігаються окремо й не входять у основну матрицю.

Кошторис B був менше $0.001 за короткий OpenAI-текст, користувач дозволив максимум **$0.02**. Фактичний usage 603 input / 54 output дає оцінку **$0.00012285**. Ollama — $0 зовнішніх API-витрат, без оцінки електрики й обладнання. SDK retry вимкнули, відповідь обмежили 512 токенами, дозволений один repair фактично знадобився Ollama. Грошовий ліміт не вбудований у CLI.

Етап C — тільки після успішних B та нового погодження бюджету. Матриця: OpenAI gpt-4o-mini / Ollama llama3.2:3b × незмінені v1/v2 × temperature 0/0.7 (top_p=1) × ті самі 30 текстів = **240 первинних генерацій**, із них 120 OpenAI. Repair і мережеві retry збільшують кількість викликів. Промпти переглянуті: обидва вимагають результат за схемою; v2 також згадує enum. Окремий новий промпт не створено, словники передає JSON Schema. Підгонки за golden не виконувалось.

Історичні 60 OpenAI-генерацій при T=0.7 використали 121862 input / 3078 output tokens: $0.0201261 за повним тарифом. На цій основі плановий діапазон C був **$0.04–$0.10**, користувач погодив максимум **$0.25** із запасом. Фактично C використав 270244 input / 5819 output tokens і коштує оцінено **$0.044028**. Розрахунок: input_tokens × $0.15/1M + output_tokens × $0.60/1M за [офіційною сторінкою GPT-4o mini](https://developers.openai.com/api/docs/models/gpt-4o-mini), snapshot 26.10.2026; без cache-знижок. Це оцінка, не рахунок провайдера. Для нової моделі, тарифу чи повтору потрібні перерахунок і новий дозвіл.

Під час C фіксуються порядок запусків і перший локальний виклик із можливим cold start. Якщо окремого warm-up/cold вимірювання немає, це явно зазначається; змішані latency не видаються за steady state. Після C створюються нові evaluator/metrics звіти й новий REPORT із фактичними показниками та 3–5 реальними помилками. Порівняння зі strings-історією враховує одночасну зміну контракту; покращення до вимірювань не заявляється.
