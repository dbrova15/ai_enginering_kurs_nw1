Локально в чистій копії перевірено індексацію 2021 чанка та Recall@5 0,8484 за порога 0,80. Платний API для цієї перевірки не потрібен.
- Експериментальний RAG-промпт `v2` просить називати підтверджену модель компонента й цитувати чанк із маркуванням. Доступний через `config/hw2-v2.json`, типовим лишається `v1`. Офлайн-перевірки пройшли, якість відповідей `v2` ще не виміряно.
- До корпусу ДЗ2 додано довідку за перевіреними посиланнями статті про робота, що їздить по лінії. Пошук охоплює TCRT5000, Arduino Nano V3 та альтернативні драйвери L298N і mini-L298N. Оновлено індекс і доказ для `hr-q07`. Перевірка: новий доказ на другому місці, альтернативні драйвери в top-5, структурна перевірка 20 питань і 40 RAG-тестів пройшли.
- Локальний RAG-конвеєр ДЗ2: 36 погоджених HTML/PDF → очищення/структурні чанки → E5/Qdrant + BM25/RRF + BGE INT8 reranking → відповіді з citation IDs, retry/repair і бюджетом. Додано `hardware_rag/`, `config/`, `data/hw2/`, `prompts/rag/`, `evals/hw2/`; `main.py rag` зберігає старий CLI через `provider_config.py`. Поточний extract-6 містить 2016 чанків, зберігає code literals у legacy HTML paragraphs, звільняє PDF page caches; фінальний індекс реально побудовано на Windows із batch=4 та CPU arenas disabled після memory/incomplete failures. Окремий локальний retrieval підтвердив recall@5 vector/hybrid/rerank 0.7337/0.6393/0.7389 і MRR@5 0.7778/0.7167/0.9333 на 15 draft-кейсах. Єдиний дозволений 20-case OpenAI run extract-4 коштував за usage $0.02885940 із cap $0.25, без failed/repair/retry; його відповіді не приписуються extract-6. `evals/hw2/REPORT.md` містить реальні metrics/cost/latency, п'ять зауважень та форми людського review без автоматичного затвердження labels. Перевірка: по 112 офлайн-тестів і `pip check` на Windows/Python 3.11 та Ubuntu WSL/Python 3.12, model inference на обох платформах, повторне відтворення report без API; усі 74 захищені файли ДЗ1 незмінні. Приймання ДЗ2 відкрите: recall <0.8, testset draft, judge не калібрований, відповіді extract-6 не виміряні. ### Виправлено
- Git відновлює історичний golden ДЗ1 і вісім JSONL із переносами CRLF, які відповідають збереженим SHA-256. Перевірено всі дев’ять хешів і 113 тестів у чистій локальній копії. Історичні дані, метрики та правила валідації збережено.
- Артефакти ingestion ДЗ2 використовують UTF-8 із переносами LF. Git зберігає LF під час checkout, а SHA-256 перевіряється за сирими байтами. Перший LF-комплект перезібрано з перевірених артефактів під новим dataset ID, збережено вміст 2016 чанків. Структурну перевірку 20 питань пройдено. Історичні прогони збережено.
- Строгий контракт нової Schema v2 `schema-v2-enums-1` (`schema_contracts.py`, `main.py`): канонічні enum платформ/інтерфейсів, strict-типи, відхилення дублікатів та одна repair-спроба зі збереженням первинної відповіді. Провайдер читається з оточення/.env; JSONL містить provider, requested/actual model, contract version/hash і статус першої спроби, мережеві помилки не розкривають приватну конфігурацію. Нові результати й звіти відокремлено від `schema-v2-strings-1`; заморожена legacy-модель відтворює старі оцінки. Evaluator/aggregator/report generator відхиляють змішані контракти, перевіряють нові source/input за TXT, показують aggregate accuracy восьми та content accuracy семи полів; нові чернетки не замінюють REPORT.md. README, .env.example, AGENTS та документацію промптів узгоджено. Перевірка етапу A: 72 офлайн-тести — OK, mock трьох провайдерів, відтворено 8 історичних груп / 240 обробок; SHA-256 усіх 48 захищених файлів незмінні. TXT, golden, v1/v2 промпти, старі результати й REPORT.md не переписані. Реальних probes/нової матриці не запускали: підтримку endpoint і вплив на якість ще потрібно виміряти після окремого дозволу. План і кошторис — `docs/SCHEMA_V2_CONTRACTS.md`.
- Працездатний CLI для Schema v2: виправлено точку входу, корінь проєкту та шлях до golden, UTF-8 промптів, імпорти й повернення конфігурації провайдера.
