Найвищі виміряні aggregate/content — OpenAI v2/T=0.7: 92.50%/91.43%; один прогін і 10 golden не доводять стабільної переваги. Обидва endpoint прийняли JSON Schema, фінальні enum/unique пройшли перевірку; пропуски wifi/usb в Ollama залишились фактичною помилкою витягування. Оцінена API-вартість за usage 603/54 — $0.00012285 із дозволених $0.02. Джерела й протокол — `results/probes/schema-v2-enums-1/20261026T172803893529Z/`; README і документацію актуалізовано. Probes не є golden-оцінюванням, нові 240 генерацій не запускались; старі дані й REPORT збережені, production-рішення не змінено.
- Офлайн-генератор чернетки звіту (`generate_report.py`, оформлення — `report_rendering.py`): явно вибрані evaluator/metrics JSON звіряються за повними конфігураціями, golden та хешами всіх первинних JSONL, оцінки й метрики перевіряються повторним розрахунком. Створено `REPORT.draft.md` із таблицями 8 конфігурацій, field accuracy, списковими P/R/F1, latency/usage/вартістю, припущеннями й 5 різнотипними розбіжностями з різних статей. Причини, висновки, production-вибір та умови перегляду позначено для заповнення автором; готові файли не перезаписуються, `REPORT.md` не створювався. Перевірка: 51 офлайн-тест — OK; реальні джерела звірено, модельних запитів не було. Чернетка не є завершеною здачею чи підтвердженим production-рішенням.

JSON/Markdown зберігають джерела, хеші, тарифи й припущення; невідомі дані не прирівнюються до нуля, локальні API-витрати відокремлено від обладнання/електроенергії. Перевірка: 42 офлайн-тести — OK; на 8 прогонів / 240 обробок створено `results/metrics/runs_20261026T101448227707Z.json` і `.md`. Cold start окремо не виміряний, тарифи — snapshot 26.10.2026, витрати не є рахунком провайдера; відповідність model ID провайдеру явно припускається через відсутність provider у первинних JSONL. Первинні результати, golden і промпти не змінено; нових модельних запитів не було.

Код, постійні налаштування, промпти й golden не змінено. Стабільна перевага другої конфігурації не доведена; cold-start benchmark і production-рішення не формувалися.

Звіт зберігає хеші входів, конфігурації та розбіжності для golden ID; missing/failed/invalid не виключаються зі знаменника, дублікати ID і несумісні входи відхиляються. ### Виправлено
- Строгий контракт нової Schema v2 `schema-v2-enums-1` (`schema_contracts.py`, `main.py`): канонічні enum платформ/інтерфейсів, strict-типи, відхилення дублікатів та одна repair-спроба зі збереженням первинної відповіді. Провайдер читається з оточення/.env; JSONL містить provider, requested/actual model, contract version/hash і статус першої спроби, мережеві помилки не розкривають приватну конфігурацію. Нові результати й звіти відокремлено від `schema-v2-strings-1`; заморожена legacy-модель відтворює старі оцінки. Evaluator/aggregator/report generator відхиляють змішані контракти, перевіряють нові source/input за TXT, показують aggregate accuracy восьми та content accuracy семи полів; нові чернетки не замінюють REPORT.md. README, .env.example, AGENTS та документацію промптів узгоджено. Перевірка етапу A: 72 офлайн-тести — OK, mock трьох провайдерів, відтворено 8 історичних груп / 240 обробок; SHA-256 усіх 48 захищених файлів незмінні. TXT, golden, v1/v2 промпти, старі результати й REPORT.md не переписані. Реальних probes/нової матриці не запускали: підтримку endpoint і вплив на якість ще потрібно виміряти після окремого дозволу. План і кошторис — `docs/SCHEMA_V2_CONTRACTS.md`.
- Працездатний CLI для Schema v2: виправлено точку входу, корінь проєкту та шлях до golden, UTF-8 промптів, імпорти й повернення конфігурації провайдера. Вихідні TXT та golden не змінюються, еталонні мітки не надсилаються моделі. Перевірка: усі 15 офлайн-тестів — OK, CLI `--help` — OK, `pip check` — OK. Платні запити й моделі не запускалися; сумісність конкретних endpoint з JSON Schema та sampling потребує окремої перевірки. Цей CLI реалізує лише Schema v2, вибір `--schema-version v2` явний; оцінювання golden та повна матриця експериментів сюди не входять.
